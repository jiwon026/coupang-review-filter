# 계획 3b: 랜딩 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 임시 첫 화면을 설치를 유도하는 랜딩으로 바꾸고, 방문부터 설치 버튼 누름까지를 계측한다.

**Architecture:** 사이트의 `/` 한 페이지. 정적 HTML 에 esbuild 로 묶은 스크립트 하나(`assets/landing.js`)를 얹는다. 스크립트는 방문자 번호, 유입원, 화면 종류, 실험 배정을 각각 순수 함수 모듈로 계산하고 `tracker` 한 곳에서 공통 프로퍼티를 붙여 앰플리튜드로 보낸다. 확장 패키지는 건드리지 않는다. 랜딩과 확장은 사람 단위로 잇지 않고 집계 수준으로 잇는다.

**Tech Stack:** 정적 HTML, plain ES modules, esbuild, Vitest + jsdom, Amplitude HTTP API V2, Vercel(main 자동 배포), sharp(사진 가공)

**Spec:** `docs/superpowers/specs/2026-09-28-coupang-review-filter-design.md`. **12절(2026-10-03 개정: 랜딩)이 이 계획의 근거다.** 12절은 3.4, 5.3, 6.1, 11.5, 6.2 일부, 6.3 의 랜딩 이벤트, 6.6 의 F1, 6.8 의 `exp_install_cta` 를 대체한다.

## 이 프로젝트의 계획 작성 방식

태스크마다 **결정, 인터페이스, 정확한 문구, 필수 테스트, 필수 변이**를 적는다. 구현 코드 전문은 싣지 않는다(계획 3a 와 같은 방식). 컨트롤러는 태스크를 보내기 전에 현재 코드를 읽고 해당 절을 브리프로 옮긴다. 코드와 이 문서가 어긋나면 코드가 우선이고 어긋난 점을 원장(`.superpowers/sdd/2026-10-03-landing/progress.md`)에 Ruling 으로 남긴다.

리뷰를 맡길 때마다 **"이 데이터로 분석이 되는가"** 를 따로 묻는다. 이 프로젝트에서 반복된 결함은 코드는 동작하는데 데이터가 거짓말을 하는 종류였다.

## Global Constraints

- **확장 패키지(`extension/`)를 수정하지 않는다.** 수정하면 재심사다. 이 계획의 변경은 `site/`, `tests/`, `scripts/`, `docs/`, `dev/` 에만 있다
- Vercel 프로젝트 `review-remover` 와 주소 `https://crf-review-remover.vercel.app` 를 바꾸거나 지우지 않는다. Web Analytics, Speed Insights 를 켜지 않는다
- main 에 푸시하면 바로 배포된다. 작업은 `feat/landing` 에서 하고, Task 8 에서만 main 에 합친다
- 사이트의 앰플리튜드 키와 연락처 이메일은 빌드 시 환경 변수로만 들어온다. 커밋하지 않고 출력하지 않는다. `extension/src/shared/config.local.js` 는 열지 않는다
- 사이트 코드는 확장 소스를 가져오지 않는다(패키지 경계). 필요한 것은 사이트 안에 다시 쓴다
- 사이트 스크립트에 innerHTML, outerHTML, insertAdjacentHTML 을 쓰지 않는다. `console.log` 를 남기지 않는다
- 페이지는 원격 자원(글꼴, 스크립트, 이미지)을 불러오지 않고 인라인 스크립트가 없다. 모든 `src`, `link[href]` 는 `/` 로 시작한다
- 랜딩이 보내는 값: 유입은 도메인만, UTM 은 `/^[a-z0-9_-]{1,40}$/i` 에 맞는 값만 소문자로. 전체 주소, 경로, 다른 쿼리, 조각의 내용은 이벤트에 싣지 않는다 (명세 12.5)
- 공통 프로퍼티(`surface`, `device_class`, `entry_source`, `exp_install_cta`, `store_live`)는 이벤트 프로퍼티가 덮어쓸 수 없다
- 계측은 페이지에 얹히지 페이지의 전제가 아니다. 저장소 접근, 전송, 공유, 복사가 실패해도 화면은 동작한다. 실패는 삼킨다
- 계측 제외(`crf_site_optout`), 자동화 브라우저(`navigator.webdriver === true`), 키 없음(개발 빌드)에서는 네트워크 요청이 0건이다
- 명세 4.4절의 관측을 랜딩 문구에 쓰지 않는다. 예시 숫자에는 `예시` 를 붙인다
- 사진에 리뷰어 이름(가려진 이름 포함), 상품 이름, 리뷰 본문이 읽히면 안 된다
- 사용자에게 보이는 모든 문구는 한국어로 쓰고 엠대시와 가운데 점을 쓰지 않는다. 코드 주석, 문서, 커밋 메시지도 같다
- 커밋 메시지는 conventional commits, 설명은 한국어. `Co-Authored-By` 같은 attribution 줄을 붙이지 않는다
- 모든 태스크는 TDD 로 하고 지정된 변이를 적용해 테스트가 실패함을 확인한 뒤 원복한다. 변이가 실패하지 않으면 테스트를 고친다. 구현자는 이 문서의 테스트가 공허하다고 판단하면 고칠 권한이 있다
- 처리방침을 고칠 때 확장의 실제 동작과 계속 일치하는지 대조한다
- 외부 환경에 대한 사실(스토어 대시보드, 앰플리튜드의 표시, 실제 브라우저 동작)은 추정하지 않고 직접 열어 확인한다
- 사용자 터미널은 Windows PowerShell 5.1 이다. 문서의 명령 예시에 `&&` 를 쓰지 않는다

### Task 1: 방문자 번호와 계측 제외

**Files:**
- Create: `site/src/landing/visitor.js`
- Test: `tests/site-landing-visitor.test.js`

**Interfaces:**
- Produces:
  - `DEVICE_KEY = 'crf_site_device_id'`, `OPTOUT_KEY = 'crf_site_optout'`
  - `readCommand(hash): 'optout' | 'optin' | null`. `#notrack` 이면 `optout`, `#track` 이면 `optin`, 그 밖은 `null`. 정확히 일치할 때만
  - `resolveVisitor({ storage, hash, randomUUID }): { deviceId: string, optedOut: boolean, persisted: boolean, command: 'optout' | 'optin' | null }`

**결정:**
- `storage` 는 `getItem`, `setItem`, `removeItem` 을 가진 객체다. 어느 호출이든 예외를 던질 수 있고(사파리 사생활 보호 모드, 저장소 차단) 그때는 그 페이지 로드에서만 쓰는 번호를 만들어 `persisted: false` 로 돌려준다
- 저장된 번호가 UUID 형식(`/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i`)이 아니면 새로 만들어 덮어쓴다. 저장소의 값도 신뢰 경계 밖의 입력이다
- `optout` 명령은 `OPTOUT_KEY` 에 `'1'` 을 쓰고, `optin` 은 지운다. 명령이 없으면 저장된 값을 따른다. 저장에 실패해도 그 페이지 로드에서는 명령대로 `optedOut` 을 돌려준다
- 계측 제외여도 방문자 번호는 만든다(제외를 알리는 화면에 번호를 보여 줘야 삭제 요청을 받을 수 있다)

**필수 테스트:**
- 처음이면 새 UUID 를 만들어 저장하고, 두 번째 호출은 같은 번호를 돌려준다
- 저장된 값이 UUID 가 아니면 새로 만들어 덮어쓴다
- `getItem` 이 던지면 `persisted: false`, 번호는 UUID, 예외가 밖으로 나오지 않는다. `setItem` 만 던지는 경우도 같다
- `#notrack` 으로 `optedOut: true` 가 되고 다음 호출(해시 없음)에서도 유지된다. `#track` 으로 풀리고 다음 호출에서도 풀려 있다
- `#notrack2`, `#x&notrack`, 빈 문자열은 명령이 아니다

**필수 변이:** (1) UUID 검사를 지우면 "UUID 가 아니면 새로" 가 실패 (2) `optout` 을 저장하지 않으면 "다음 호출에서도 유지" 가 실패 (3) try 를 벗기면 예외 테스트가 실패 (4) `readCommand` 를 `includes` 로 바꾸면 `#notrack2` 테스트가 실패

- [ ] Step 1: 위 테스트를 쓴다. Step 2: `npx vitest run tests/site-landing-visitor.test.js` 로 실패를 확인한다. Step 3: 구현한다. Step 4: 통과를 확인한다. Step 5: 변이 네 가지를 하나씩 적용해 실패를 확인하고 원복한다. Step 6: `git commit -m "feat: 랜딩 방문자 번호와 계측 제외"`

### Task 2: 유입원과 화면 종류

**Files:**
- Create: `site/src/landing/source.js`, `site/src/landing/device.js`
- Test: `tests/site-landing-source.test.js`, `tests/site-landing-device.test.js`

**Interfaces:**
- Produces:
  - `normalizeUtm(value): string | null`
  - `referrerDomain(referrer, ownHost): string | null`
  - `resolveSource({ search, referrer, ownHost }): { utm_source, utm_medium, utm_campaign, referrer_domain, entry_source }` (앞의 넷은 `string | null`, `entry_source` 는 항상 문자열)
  - `deviceClass({ userAgent, uaDataMobile, maxTouchPoints }): 'desktop' | 'mobile'`

**결정:**
- `normalizeUtm`: 문자열이고 `/^[a-z0-9_-]{1,40}$/i` 에 맞으면 소문자로, 아니면 `null`. 주소는 누구나 만들 수 있으므로 자유 텍스트(이메일, 한글, 공백)가 통계에 섞이지 않게 한다
- `referrerDomain`: `new URL(referrer).hostname` 을 소문자로, 앞의 `www.` 와 `m.` 을 뗀다. 프로토콜이 http, https 가 아니거나 파싱에 실패하면 `null`. 호스트가 `ownHost` 와 같으면 `'internal'`(처리방침에서 돌아온 경우를 외부 유입과 구분한다)
- `entry_source` 의 우선순위: `utm_source` → `referrer_domain` → `'direct'`
- `utm_source=handoff` 는 그대로 `handoff` 다. 원래 유입원은 `utm_campaign` 에 실려 온다(Task 4)
- `deviceClass`: `uaDataMobile` 이 boolean 이면 그 값을 따른다. 아니면 `userAgent` 가 `/Android|iPhone|iPad|iPod|Mobile/i` 에 맞으면 `mobile`. 판정 불가(빈 문자열)는 `desktop` 이다. **아이패드는 기본으로 맥 사파리의 UA 를 보내므로** UA 에 `Macintosh` 가 있고 `maxTouchPoints > 1` 이면 `mobile` 로 본다(실제 맥은 0 이다). 이 판정이 없으면 설치할 수 없는 아이패드 방문자가 PC 전용 실험에 섞여 클릭률을 희석한다. 데스크톱 모드를 켠 안드로이드 태블릿은 터치 노트북과 구분할 수 없어 `desktop` 으로 남는다(알려진 한계, 3c 에 넘긴다)

**필수 테스트:**
- `normalizeUtm`: `'Clien'` → `'clien'`, `'a_b-1'` 통과, 41자, 빈 문자열, `'a b'`, `'a@b.com'`, `'한글'`, `null`, 숫자형은 `null`
- `referrerDomain`: `https://www.clien.net/service/board/park/123?x=1` → `clien.net`(경로와 쿼리가 결과에 없다), `https://m.ppomppu.co.kr/` → `ppomppu.co.kr`, `android-app://com.kakao.talk` → `null`, `''` → `null`, 자기 호스트 → `internal`
- `resolveSource`: UTM 이 있으면 그것이 `entry_source`, 없고 유입 도메인만 있으면 도메인, 둘 다 없으면 `direct`. 잘못된 `utm_source` 는 버리고 도메인으로 넘어간다. `search` 의 다른 쿼리(`?email=a@b.com&utm_source=x`)는 결과 어디에도 없다
- `deviceClass`: 실제 UA 문자열 네 개(윈도우 크롬, 맥 사파리, 아이폰 사파리, 안드로이드 크롬)를 줄이지 않고 넣는다. `uaDataMobile: true` 가 데스크톱 UA 를 이긴다. `uaDataMobile: undefined` 면 UA 로 판정

**필수 변이:** (1) `normalizeUtm` 의 길이 제한을 지우면 41자 테스트 실패 (2) 정규식의 앵커를 지우면 `'a@b.com'` 테스트 실패 (3) `hostname` 을 `href` 로 바꾸면 경로 테스트 실패 (4) 우선순위를 뒤집으면 `entry_source` 테스트 실패 (5) `uaDataMobile` 분기를 지우면 "이긴다" 테스트 실패

### Task 3: 실험 배정

**Files:**

**결정:**
- 모바일은 저장소를 읽지도 쓰지도 않고 `none` 이다
- PC 는 저장된 값이 `VARIANTS` 에 있으면 그 값, 아니면 `random() < 0.5 ? 'hero_only' : 'hero_sticky'` 로 정해 저장한다
- 확장의 결정적 해시 배정과 다르게 저장 방식인 이유: 방문자 번호를 저장하지 못한 방문자도 배정해야 하고, 실험이 하나뿐이라 실험 간 상관을 걱정할 일이 없다
- 저장소가 던지면 그 페이지 로드에서만 무작위로 정한다

**필수 테스트:** 모바일은 `none` 이고 저장소 호출이 0번이다. `random` 0.49 → `hero_only`, 0.5 → `hero_sticky`. 저장된 변형이 `random` 을 이긴다. 저장된 값이 목록 밖(`'x'`, `'none'`)이면 다시 정한다. 저장소가 던져도 변형을 돌려준다. `random` 을 1만 번 균등 표본으로 돌리면 두 변형의 비율이 각각 0.48~0.52 다

**필수 변이:** (1) 모바일 분기를 지우면 실패 (2) 저장을 지우면 "저장된 변형이 이긴다" 의 앞 단계가 실패 (3) 임계값을 0.9 로 바꾸면 비율 테스트 실패 (4) 목록 검사를 지우면 `'x'` 테스트 실패

- 계측 제외 명령(`#notrack`, `#track`)을 읽은 뒤 `history.replaceState` 로 조각을 지운다. `#notrack` 이면 `#optout-notice` 에 `이 브라우저의 방문은 더 기록하지 않습니다. 방문자 번호: <번호>` 를 `textContent` 로 넣어 보인다. `#track` 이면 `이 브라우저의 방문을 다시 기록합니다.`

- `Landing Viewed` 는 `document.visibilityState === 'visible'` 일 때 바로, 아니면 처음 보이게 될 때(`visibilitychange`) 한 번 보낸다. 프로퍼티: `referrer_domain`, `utm_source`, `utm_medium`, `utm_campaign`(없는 값은 싣지 않는다)
- `Demo Viewed`: `#demo` 가 절반 이상 보일 때 한 번(`IntersectionObserver`, `threshold: 0.5`), 보낸 뒤 관찰을 끊는다
- `Install CTA Clicked`: `#cta-hero` 는 `cta_location: 'hero'`, `#cta-sticky` 는 `'sticky'`. 이동을 막지 않는다(`preventDefault` 를 부르지 않는다). 전송은 `keepalive` 라 페이지를 떠나도 나간다. 누를 때마다 보낸다
- `Handoff Link Requested`: 복사는 `navigator.clipboard.writeText(handoffUrl(...))`. 성공하면 `#handoff-status` 에 `복사했습니다`, 실패하면 `복사하지 못했습니다. 주소창의 주소를 직접 복사해 주세요`. 공유는 `navigator.share({ title: '체험단 리뷰 제거기 for 쿠팡', url })`. 사용자가 공유 창을 닫아 거부돼도 아무것도 보이지 않는다. **이벤트는 버튼을 누른 시점에 보낸다**(성공 여부와 무관. 의향을 재는 이벤트다)
