# 계획 4: 무신사 지원 (1.1.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 확장이 무신사 상품 페이지와 후기 전체보기에서도 체험단 후기를 표시하고 숨기고 체험단을 뺀 평점을 보여 주게 한다. 쿠팡 쪽 동작은 그대로 둔다.

**Architecture:** 콘텐츠 스크립트에서 쇼핑몰마다 다른 부분(주소, 선택자, 체험단 문구, 정렬, 구매 버튼, 숨기는 방식, 관측 단위)을 "쇼핑몰 부품" 객체 하나로 모은다. 부품은 `extension/src/content/sites/` 에 쇼핑몰당 파일 하나다. 누적, 평점, 배지, 배너, 건강 신호, 전송은 공통 코드가 부품을 받아서 쓴다. 모든 이벤트에 `site` 를 붙이고 무신사의 번호에는 `musinsa:` 를 붙여 가명 처리한다. 1.0.x 에서 동의한 기기는 1.1.0 으로 올라올 때 동의를 다시 받는다.

**Tech Stack:** Chrome MV3, plain ES modules, esbuild, Vitest + jsdom, Amplitude HTTP API V2, 크롬 헤드리스 + CDP(실브라우저 확인)

**Spec:** `docs/superpowers/specs/2026-09-28-coupang-review-filter-design.md`. **13절(2026-10-08 개정: 무신사 지원)이 이 계획의 근거다.** 13.8 에 실측한 선택자가 있다. 확인 결과의 배경은 `docs/research/2026-10-07-other-stores.md`.

## 이 프로젝트의 계획 작성 방식

태스크마다 **결정, 인터페이스, 정확한 문구, 필수 테스트, 필수 변이**를 적는다. 구현 코드 전문은 싣지 않는다(계획 3a, 3b 와 같은 방식). 컨트롤러는 태스크를 보내기 전에 현재 코드를 읽고 해당 절을 브리프로 옮긴다. 코드와 이 문서가 어긋나면 코드가 우선이고 어긋난 점을 원장(`.superpowers/sdd/2026-10-08-musinsa/progress.md`)에 Ruling 으로 남긴다.

리뷰를 맡길 때마다 **"이 데이터로 분석이 되는가"** 를 따로 묻는다.

## Global Constraints

- **쿠팡에서의 동작을 바꾸지 않는다.** 쿠팡 페이지에서 보내는 이벤트는 `site: 'coupang'` 과 `sponsored_only_view: false` 가 더해지는 것 말고는 이름, 프로퍼티, 횟수, 순서가 같아야 한다. 쿠팡의 `product_key` 는 지금과 같은 입력(상품 번호 원문)으로 만든다
- Task 1 은 기존 테스트 파일을 고치지 않는다. 기존 테스트가 고치지 않은 채 통과해야 옮기기가 맞게 된 것이다. Task 3 과 Task 6 에서 고치는 기존 테스트는 그 태스크에 적은 것뿐이다
- `extension/src/shared/config.local.js` 를 열지도 출력하지도 커밋하지도 않는다. 키와 연락처 이메일은 어떤 파일에도 쓰지 않는다
- 무신사의 후기 목록 주소(`goods.musinsa.com/api2/...`)를 확장이 부르지 않는다. 확장은 화면에 그려진 것만 읽는다
- 무신사의 class 이름은 뒤에 바뀌는 꼬리가 붙는다. 선택자는 `data-` 속성을 먼저 쓰고, class 는 `[class*="앞부분"]` 으로만 쓴다
- 콘텐츠 스크립트의 대상은 `https://www.coupang.com/vp/products/*`, `https://www.musinsa.com/products/*`, `https://www.musinsa.com/review/goods/*` 셋이다. `permissions` 는 `storage`, `sidePanel` 그대로다. `host_permissions` 를 만들지 않는다
- 리뷰 본문, 리뷰어 이름, 상품 이름, 상품 번호 원문, 전체 주소를 이벤트에 싣지 않는다. 새 식별자를 보내려면 `background/analytics.js` 의 가명 처리 표에 넣는다
- 계측은 제품에 얹힌다. 메시지 전송, 정렬 읽기, 조건 읽기가 던져도 배지와 배너는 동작한다
- 확장 코드에 `innerHTML`, `outerHTML`, `insertAdjacentHTML` 을 쓰지 않는다. `console.log` 를 남기지 않는다(`debugLog` 와 `console.warn` 만)
- 테스트 픽스처에 실제 리뷰어 이름, 리뷰 본문, 상품 이름을 넣지 않는다. 구조만 실제와 같게 만든다
- 사용자에게 보이는 모든 문구는 한국어로 쓰고 엠대시와 가운데 점을 쓰지 않는다. 코드 주석, 문서, 커밋 메시지도 같다. 연결어미 뒤에 쉼표를 찍지 않는다
- 커밋 메시지는 conventional commits, 설명은 한국어. 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` 를 붙인다
- 모든 태스크는 TDD 로 하고 지정된 변이를 하나씩 적용해 테스트가 실패함을 확인한 뒤 원복한다. 변이가 실패하지 않으면 테스트를 고친다. 변이를 되돌릴 때는 `git diff` 가 비었는지 확인한다
- 외부 환경에 대한 사실(무신사의 마크업, 크롬의 동작)은 추정하지 않는다. 13.8 에 없는 것이 필요하면 멈추고 컨트롤러에 묻는다
- 작업 브랜치는 `feat/musinsa` 다. main 푸시는 공개 사이트가 바뀌므로 사용자 확인 뒤에만 한다. Vercel 프로젝트와 주소는 건드리지 않는다
- 사용자 터미널은 Windows PowerShell 5.1 이다. 문서의 명령 예시에 `&&` 를 쓰지 않는다

## 쇼핑몰 부품의 모양 (모든 태스크가 따른다)

```js
{
  id: 'coupang',                    // 'coupang' | 'musinsa'. 이벤트의 site 값
  hosts: ['www.coupang.com'],
  keyPrefix: '',                    // product_id, page_first_review_id 앞에 붙인다. 무신사는 'musinsa:'
  productIdOf(pathname),            // string | null. 대상 페이지가 아니면 null
  findContainer(root),              // Element | null. 후기 구역
  findItems(container),             // Element[]. 후기 카드
  readId(item),                     // string | null
  readRating(item),                 // 1~5 의 정수. 읽지 못하면 0
  markers: ['...'],                 // 체험단 문구(공백 무시하고 포함 여부로 본다)
  detectSort(root),                 // string. 읽지 못하면 'unknown'
  purchase: { cart, buyNow },       // CSS 선택자
  bannerAnchor(container),          // Element. 배너를 이 요소 바로 앞에 넣는다
  isSponsoredOnlyView(root),        // boolean. 쿠팡은 항상 false
  hiddenClass: 'crf-hidden',        // 무신사는 'crf-collapsed'
  observation: 'page',              // 'page' | 'batch'(무신사)
}
```

부품의 함수는 던지지 않는다. 찾지 못하면 null, 0, 'unknown', false 를 돌려준다.
