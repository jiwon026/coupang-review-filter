- 올린 날짜를 아래 기록에 적는다. 분석할 때 채널별 유입 시점을 맞춰 본다

## 글을 쓸 때의 원칙

- "체험단 리뷰는 가짜다" 라고 쓰지 않는다. 쇼핑몰(쿠팡, 무신사)이 체험단 표시를 붙인 리뷰를 구분해서 보고, 평균을 다시 계산해 보여 주는 도구다
- 한계를 함께 적는다: PC 크롬 전용, 숫자는 지금까지 본 리뷰 기준, 쇼핑몰의 표시 방식이 바뀌면 동작하지 않을 수 있음
- 통계는 사실대로: **동의한 경우에만 익명 사용 통계를 보낸다.** "아무것도 수집하지 않는다" 고 쓰지 않는다. 포트폴리오 분석에 쓴다는 것도 밝힌다
- 쿠팡, 무신사와 관계없는 개인이 만든 도구임을 적는다
- 다른 사람의 리뷰 본문, 이름, 상품이 드러나는 사진을 쓰지 않는다. 사진은 `site/public/img/` 의 세 장이나 `release/screenshots/store/` 의 다섯 장을 쓴다

## 초안 1: 티스토리 글

2026-10-07 다시 씀. 사용자가 처음 초안을 "AI 말투가 난다" 고 해서, 사용자가 슬랙에 직접 쓴 글의 말투(해요체, 짧은 문장)에 맞춰 고쳤다. 2026-10-12 에 1.1.0(무신사 지원, 이름 변경, 패널의 숨기기 버튼)을 반영했다.

**제목:** 쿠팡, 무신사 체험단 리뷰만 숨겨 주는 크롬 확장 만들었어요

쿠팡에서 뭐 살 때 리뷰부터 보잖아요. 근데 요즘은 리뷰 첫 줄에 "쿠팡체험단 이벤트로 상품을 무료로 제공받아 작성한 구매 후기" 라고 적힌 게 너무 많더라고요. 저는 자기 돈 주고 산 사람 얘기가 궁금한 건데요.

그래서 체험단 리뷰만 골라서 표시해 주고 숨겨 주는 크롬 확장을 만들었어요. 이름은 "체험단 리뷰 제거기" 입니다. 처음에는 쿠팡에서만 됐는데 무신사에서도 되면 좋겠다는 얘기를 듣고 무신사도 넣었어요.

저는 커머스 데이터 분석을 공부하고 있는데 포트폴리오로 뭘 만들까 하다가 이걸 골랐어요.

(사진: 배너)

**이런 걸 해 줘요**

쿠팡이나 무신사 상품 페이지에서 리뷰 쪽으로 내려가면 리뷰 위에 작은 배너가 하나 떠요. 거기에 원래 평점이랑 체험단 리뷰를 뺀 평점이 나란히 나옵니다. 체험단 리뷰가 몇 개인지도 같이 보여 줘요.

배너에 있는 "체험단 리뷰 숨기기" 버튼을 누르면 체험단 리뷰가 싹 사라져요. 다시 보고 싶으면 "체험단 리뷰 다시 보기" 를 누르면 됩니다. 옆에 열리는 패널에도 같은 버튼이 있어요.

체험단 리뷰에는 표시도 붙여 줘서 숨기지 않고 봐도 구분이 돼요.

(사진: 배지, 패널)

**체험단인지 어떻게 아냐면**

쿠팡이랑 무신사는 체험단 리뷰에 안내 문구를 직접 붙여 놓거든요. 그 문구가 있는 리뷰만 체험단으로 봅니다. 말투가 광고 같다고 제 마음대로 체험단이라고 찍지는 않아요.

**미리 말씀드릴 것**

PC 크롬에서만 돼요. 휴대폰이나 쇼핑몰 앱에서는 못 씁니다.

숫자는 상품 전체 리뷰가 아니라 지금까지 화면에 뜬 리뷰만 가지고 계산해요. 쿠팡은 리뷰 2페이지, 3페이지로 넘기면, 무신사는 후기 전체보기에서 스크롤하면 본 만큼 더해집니다.

체험단 리뷰가 다 나쁘다는 건 아니에요. 구분해서 볼 수 있게 해 주는 도구입니다.

쿠팡, 무신사랑은 아무 관계 없이 제가 혼자 만든 거예요.

**통계 얘기**

설치하면 익명 사용 통계를 보내도 되는지 먼저 물어봐요. 괜찮다고 한 경우에만 배너가 몇 번 떴는지, 버튼을 눌렀는지 같은 기록을 보냅니다. 리뷰 내용, 상품 이름, 상품 주소는 안 보내요. 싫다고 해도 기능은 똑같이 다 쓸 수 있고 나중에 패널에서 언제든 끌 수 있어요.

이 통계는 확장이 잘 돌아가는지 확인하고 제 포트폴리오 분석에 씁니다. 자세한 건 개인정보 처리방침에 적어 놨어요.

**설치는 여기서**

무료고 광고도 없어요. 아래 주소에서 "크롬에 추가" 누르면 됩니다.

https://crf-review-remover.vercel.app/?utm_source=tistory&utm_medium=blog&utm_campaign=launch

써 보시다가 이상한 데 있으면 댓글로 알려 주세요. 바로 고쳐 볼게요!

## 초안 4: 긱뉴스 Show GN

올리기 전에 https://news.hada.io/guidelines 를 다시 읽는다. "직접 써 볼 수 있는 결과물" 이어야 하고 이미지와 단축 주소는 쓸 수 없다. 같은 프로젝트는 다시 올리기 어렵다.

**제목:** Show GN: 쿠팡과 무신사 리뷰에서 체험단 리뷰를 표시하고 숨기는 크롬 확장

**주소:** 긱뉴스용 링크(위 표)

**본문:**

쿠팡과 무신사 상품 페이지의 리뷰에서 체험단 제공 리뷰를 표시하고, 숨기고, 그 리뷰를 뺀 평점을 보여 주는 크롬 확장입니다. 커머스 데이터 분석 포트폴리오로 만들었습니다.

- 판별: 쇼핑몰이 리뷰에 직접 붙이는 체험단 안내 문구로만 판별합니다. 추측하지 않습니다
- 범위: 숫자는 지금까지 화면에 나온 리뷰를 기준으로 누적합니다. 전체 리뷰를 긁어 오지 않습니다
- 권한: `storage`, `sidePanel` 두 개뿐이고 쿠팡 상품 페이지, 무신사 상품 페이지와 후기 전체보기에서만 동작합니다
- 통계: 설치 직후 화면에서 동의한 경우에만 익명 사용 통계를 보냅니다. 상품 번호는 기기마다 다른 값과 섞어 되돌릴 수 없게 바꾼 뒤에만 보내고, 리뷰 내용은 보내지 않습니다
- 한계: PC 크롬 전용이고 쇼핑몰의 마크업이나 표시 방식이 바뀌면 고쳐야 합니다

써 보시고 잘못 판별하거나 화면이 깨지는 경우를 알려 주시면 고치겠습니다.

## 초안 5: 디스콰이엇

제품을 먼저 등록하고 승인을 받은 뒤 글을 쓴다. 크롬 확장을 제품으로 등록할 수 있는지는 등록 화면에서 직접 확인한다.

**제품 한 줄 소개:** 쿠팡과 무신사 리뷰에서 체험단 리뷰를 표시하고 숨기고, 뺀 평점을 보여 주는 크롬 확장

**글:**

커머스 데이터 분석 포트폴리오로 크롬 확장을 만들어 스토어에 올렸습니다.

분석을 하려면 데이터가 있어야 하는데, 공개 데이터셋을 받아 쓰는 대신 사람들이 실제로 쓰는 걸 만들고 그 사용 기록을 분석해 보고 싶었습니다. 그래서 쿠팡 리뷰에서 체험단 리뷰를 구분해 보여 주는 확장을 만들었습니다. 첫 버전을 올린 뒤 "무신사에서도 되면 좋겠다" 는 의견을 받아 무신사를 더했습니다.

만들면서 방향을 가장 크게 바꾼 건 기능이 아니라 "무엇을 수집해도 되는가" 였습니다. 처음에는 설치하면 바로 기록을 보내게 했다가, 스토어 정책을 읽고 설치 직후에 동의를 받는 방식으로 바꿨습니다. 상품 번호도 원문 대신 되돌릴 수 없는 값으로 바꿔 보냅니다.

PC 크롬 전용이고 무료입니다. 써 보시고 의견 주시면 고맙겠습니다.

### 구글 애널리틱스 연결 (선택)

스토어 대시보드는 "어느 링크로 들어와 설치했는지" 를 보여 주지 않는다. 채널별 설치 수를 보려면 구글 애널리틱스(GA4) 속성을 만들어 스토어 항목에 연결해야 한다.

- 연결하면: 랜딩이 스토어 링크에 붙이는 표식(`utm_source` 는 유입원, `utm_campaign` 은 설치 버튼 실험 변형)별 설치 수를 볼 수 있다
- 연결하지 않으면: 설치 수는 전체 합계로만 본다. 랜딩의 `Install CTA Clicked` 까지는 채널별로 보인다
- 치르는 것: 구글 계정으로 GA4 속성을 만들어야 하고, 스토어 등록 페이지 방문자가 구글 애널리틱스로 측정된다. 스토어 등록정보 변경이라 다시 검토를 받을 수 있다
- 연결한 뒤 확인할 것: GA4 에서 `utm_source=direct`, `utm_medium=landing` 인 방문은 "(direct) / (none)" 이 아니라 `direct / landing` 으로 보인다

### 사진을 바꿀 때

- 랜딩: 새 사진을 `release/screenshots/raw/` 에 넣고 `scripts/build-site-images.js` 의 원본 경로를 맞춘 뒤 `node scripts/build-site-images.js` 를 실행한다. 결과(`site/public/img/`)를 눈으로 열어 이름, 상품명, 리뷰 본문이 읽히지 않는지 확인하고 커밋, 푸시한다. `index.html` 의 `width`, `height` 도 실제 크기로 고친다
- 스토어: `release/screenshots/make.mjs` 나 `make-v2.mjs` 로 1280x800 사진을 만들어 대시보드에서 교체하고 검토를 위해 제출한다. 검토 중에도 게시된 것은 그대로 유지된다
